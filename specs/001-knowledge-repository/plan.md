## Summary

Build a centralized learning repository system that captures, enriches, and retrieves development knowledge across all projects using webhook endpoints, Notion for structured storage, Supabase with pgvector for semantic search, and OpenAI for AI enrichment. The system includes session tracking with replay capability using asciinema recordings. Primary components: n8n workflows for orchestration, three Notion databases (Projects, Learnings, Sessions), Supabase vector store, and webhook API endpoints for capture/query operations.

### Supabase Database

```sql
-- Vector embeddings table
CREATE TABLE learnings_vectors (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  learning_id text UNIQUE NOT NULL,
  content text NOT NULL,
  embedding vector(1536) NOT NULL,
  metadata jsonb NOT NULL,
  created_at timestamp with time zone DEFAULT now()
);

-- Create vector similarity search index
CREATE INDEX ON learnings_vectors USING ivfflat (embedding vector_cosine_ops);
```

## Integration Points

### 1. Notion API
- **Purpose**: Structured storage for Projects, Learnings, Sessions
- **Authentication**: Integration token (kept in n8n credentials)
- **Rate Limits**: 3 requests/second (implement queuing in n8n)
- **Key Operations**: Create page, Query database, Update properties

### 2. Supabase
- **Purpose**: Vector similarity search with pgvector
- **Authentication**: API key + JWT (anon key for client operations)
- **Key Operations**: Insert embeddings, Similarity search, Metadata filtering
- **Index Type**: IVFFlat for cosine similarity

### 3. OpenAI API
- **Purpose**: Generate embeddings, AI enrichment
- **Authentication**: API key (kept in n8n credentials)
- **Models**:
  - text-embedding-3-small (1536 dimensions) for embeddings
  - gpt-4o-mini for AI categorization and tagging
- **Cost Control**: Batch requests, cache results

### 4. ngrok
- **Purpose**: Expose local n8n webhooks for development
- **Configuration**: Webhook URLs in n8n point to ngrok URL
- **Reconfiguration**: Update webhook URLs when ngrok URL changes

### 5. Claude Code
- **Purpose**: Learning capture during development sessions
- **Integration**: Custom skill or bash aliases to POST to webhooks
- **Session Tracking**: Integrate with record-claude script

## API Endpoint Summary

**Total Endpoints**: 8 webhook endpoints

| Endpoint | Method | Purpose | Input | Output |
|----------|--------|---------|-------|--------|
| `/capture_learning` | POST | Store new learning | Learning data + optional session_id, AI_Accepted flag | Learning ID + status + AI suggestions |
| `/update_learning` | POST | Update existing learning | Learning ID + updated fields | Updated learning + embedding regen status |
| `/query_learnings` | POST | Semantic search | Query + filters | Top 10 learnings with scores + feedback prompt |
| `/query_feedback` | POST | Submit query feedback | Query text + relevant learning IDs | Confirmation message |
| `/list_projects` | POST | Project catalog | Optional filters | Project list with counts |
| `/create_session` | POST | Start session | Projects + goals + recording path | Session ID + status |
| `/end_session` | POST | End session | Session ID | Updated session with duration |
| `/query_sessions` | POST | Session history | Filters (project/date/status) | Session list with replay links |
